# LR/SC 原子操作与差分测试 Bug 修复记录 (2026-05-21)

## 1. Mismatch Bug 的定位与架构修复
在进行 `difftest` 差分测试 `lr-sc-riscv32im-npc.bin` 时，遇到循环测试中周期 85 时的 `x10` (a0) 寄存器 Mismatch 以及后续的诸多问题。
这主要源自由于乱序执行架构下 `Store` 访存行为带来的可见性问题。

### 架构修正方案
经过详细分析，我们完成了以下架构改造：
1. **统一的 Reservation 追踪 (`lsu_group.sv`)**:
   - `LSU_LR` 在 `store buffer` 之前或缓存查询阶段会注册其保留地址 (`res_valid_q` 和 `res_addr_q`)。
   - `LSU_SC` 在发射到 `Store Buffer` 时，直接在 `lsu_group.sv` 中根据保留站的状态判定 `success` (是否命中) 或是 `fail`。
2. **`LSU_SC_FAIL` 假存储与占位**:
   - 如果 `LSU_SC` 失败，它将被标记为特殊的 `LSU_SC_FAIL` 发往 `Store Buffer`。
   - 在 `Store Buffer` 中，它被视作 Dummy Store，在提交时不发送 AXI / D-Cache 总线请求，而是直接清除并向 ROB (CDB) 写入对应的返回值（成功写入 0，失败写入 1）。
3. **精准消除死逻辑**:
   - 在旧有设计的 `lsu_lane.sv` 中，相关的逻辑无法捕捉全局的 Store 流，这些无效代码已被彻底精简移除。

## 2. NEMU 参考模型与 `lr-sc.c` 的冲突分析
经过上述重构，我们的 RTL 在 `difftest` 的每条指令状态对比中实现了 **完全 0 Mismatch**。
然而测试本身抛出了 `HIT BAD TRAP (code=1)` 错误。经过探查，这是由于 C 测试程序 (`lr-sc.c`) 包含了一个错误的预设断言：
```c
  asm volatile("lr.w %[old], (%[addr])\n"
               "sw   %[brk], 0(%[addr])\n"
               "sc.w %[sc], %[val], (%[addr])\n" ...);
  check(shared == 100);
```
在 RISC-V 规范中，**同一 Hart (线程)** 对保留区的额外 store 是否导致随后的 `sc` 失败是 `Implementation-Defined`（实现定义的）。
参考模型（NEMU）宽松地允许其**成功**。为了对齐该模型，我们的 RTL 也保证了同 Hart 的 Store 不会清理保留站。这导致 `shared` 被成功写入了 200。
但原测试代码的断言错误地强行认定 `shared == 100`。

### 解决办法
我们将该测试源码兼容了 RISC-V 规范的所有可能性，并且重新编译了所有 `cpu-tests`：
```c
    if (sc_result == 0) {
      check(shared == 200);
    } else {
      check(shared == 100);
    }
```
